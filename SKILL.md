# Douyin account archival

- Inspect opencli adapter limits before equating CLI output with the homepage total: user-videos caps requests at20 and its helper hardcodes max_cursor=0. Preserve full JSON and deduplicate aweme_id programmatically.
- Run browser eval using an invoked async IIFE, not an uninvoked async function. Request the normal public endpoint through the connected page with credentials and JSON headers. Persist every batch and cursor before continuing.
- Inspect `not_login_module.guide_login_tip_exist` when pagination returns only status_code=0; this can be a login gate despite has_more=1. Do not claim completion or attempt to bypass. Request normal user login; vault list first and never collect credentials in chat.
- A larger legitimate first-page count may return more public items than the CLI cap. Compare actual unique count to expected total and report missing items explicitly; never invent missing IDs.
- Classify `aweme_type` before transcription: type68 image posts can expose only background music through `video.play_addr` with duration0 metadata. Preserve every original image, verify image count and readability, extract page-numbered OCR, and summarize image content with page references. Never use BGM ASR as the post body or require a video stream for image posts; identical BGM hashes across posts do not imply duplicate image content.
- Freeze exact media locally, verify each with ffprobe, and extract 16kHz mono WAV. Ignore media, signed CDN URLs and raw browser response metadata in git; publish sanitized indexes and source IDs.
- Pin PyAV to16.1.0 with faster-whisper1.2.1 if PyAV19 reports `open() got an unexpected keyword argument metadata_errors`.
- Discover real CPU count before setting ASR threads; over-subscription can severely slow inference. Preserve timestamped raw ASR with confidence fields and clearly label uncorrected output.
- Benchmark ASR on one representative clip before scheduling the full account; estimate runtime from measured processing time and total media duration so long CPU jobs receive a durable execution path from the start.
- Resume batches from a per-source status manifest with separate downloaded, audio-verified, transcribed, summarized, and published states; atomic per-video outputs prevent repeated downloads or transcription after interruption. Track discovered IDs separately from the homepage total, since inaccessible works may have unknown IDs.
- Keep one ASR worker running while editorial summaries consume completed transcripts incrementally; do not launch competing transcription workers on a saturated CPU or restart healthy work during handoffs. Record the process handle, environment, project path, completed IDs, next action, and publication command for continuation.
- Treat delegated completion as a checkpoint until acceptance counts are verified: report downloaded, transcribed, summarized, and remotely published counts separately. A created repository or a handful of summaries does not complete an all-videos request; continue all unblocked work and state the exact remaining login dependency.
- Verify exact remote publication contents by comparing the recursive GitHub tree's blob hashes with `git ls-tree -r -z <committed-sha>`, in addition to privacy, HEAD, source IDs and artifact counts. Compare against the committed tree rather than the working directory when a healthy ASR worker is still creating new files; this avoids falsely rejecting a valid checkpoint because processing advanced during verification.
- Validate completion by source type: require complete original-image coverage, page-numbered OCR and editorial records for image posts, and verified audio plus ASR and editorial records for videos. Count background-music ASR separately; otherwise it inflates the apparent number of video transcripts. Verify remote source IDs and artifact counts after publishing, not just the remote commit SHA.
- For this user's multi-creator FDE research, keep each creator's archive and attribution distinct, then produce a cross-creator comparison and an actionable content strategy: content pillars, original topic ideas, and a repeatable scripting process. Ground agreements and disagreements in complete transcripts or OCR, cite seconds or image pages, and separate creator claims from verified evidence. Synthesize new scripts rather than presenting copied passages as original work.
- Keep progress updates concise and milestone-based: report meaningful changes in coverage, blockers, or completion rather than repeating each worker handoff. Preserve a healthy background job across handoffs and finish all unblocked editorial work before reporting a final result.
- Read long classroom pitches through their final Q&A before summarizing: later challenges or admissions of hypothetical inputs can reverse the evidentiary status of the opening claims. Preserve these limitations in both per-source notes and synthesis.
- Keep raw ASR timestamps unchanged when the engine emits a tail beyond media duration. Record the exact raw-file hash, out-of-bounds segment indices and editorial citation cutoff as a reviewed anomaly; make validation fail on any unknown anomaly or changed raw hash, and forbid summaries from citing the suspect tail. Report reviewed anomaly IDs explicitly rather than globally relaxing duration tolerance or silently clamping the transcript.
- Compare a speaker's references to a longer talk with the actual archived post duration; a short post may contain the ending of a much longer source. Read the current file to its end, label the possible slice, and never imply that the referenced longer recording was obtained or reconstructed.
- Treat zero-segment ASR as an explicit evidence-limit record with no fabricated timestamp points; it means the current ASR emitted no speech, not that the source is silent. Report empty-ASR IDs separately at acceptance.
- Preserve denominator and reporting-period limits when editing financial claims: ARR, recognized revenue, profit, markup and gross margin are different metrics. If ASR percentages or budget examples conflict, record the unclear source claim without repairing it into verified industry statistics; hypothetical channel prices do not establish realized margins.
- Preserve team-contribution admissions when editing implementation stories: distinguish the speaker's knowledge/Skill work from servers, infrastructure, integrations and maintenance owned by client or partner teams. An architecture explanation, interview puzzle or claimed API chain is not an executed integration; mark it untested until the exact target operation is run and read back.
- Keep historical analogies, repeated teaser openings and second-hand market anecdotes distinct from evidence: do not count a repeated opening as an independent case, infer universal change timelines from container/Kodak stories, or turn a speaker's newly acquired ability into a claim that the industry could not perform that work before AI.
- Keep machine-selected excerpts distinct from human summaries. Every synthesized point needs source ID and timestamp; source marketing claims are not independent verified facts.
- Store editorial summaries separately by source ID (overview, timestamped points, evidence limits); make publishing prefer those records over generated excerpts so rerunning publication cannot overwrite reviewed summaries. Validate source IDs and timestamp bounds against raw ASR before publishing.
- Create repositories private explicitly unless the user requests public visibility for that repository; a visibility change to one creator's archive does not automatically authorize making subsequent archives public. After creation or visibility changes, read the exact repository's privacy and remote HEAD back. If a delegated process must outlive its worker, use process_manage handoff before finishing.
